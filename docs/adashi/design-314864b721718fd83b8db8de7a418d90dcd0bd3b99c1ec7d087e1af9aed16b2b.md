# Compaction budget model

Normative model for how much context one automatic compaction must free and what it may spend, decided 2026-09-26 and implemented by commit 3173c99, amended the same day to remove the last absolute limits and to make the one underivable ratio a setting, and amended 2026-10-02 to lower that ratio's default to 20% and to name its unit in Settings. It supersedes the R/U/S model of 2026-09-25 (retention 0.16 W, carried-user budget U = R/2, summary S = min(R/2, shadowed span/2), absolute 64,000-token floor) and every other chosen constant.

**Every budget is a share of the window.** An earlier revision floored the replacement at 2,512 tokens and capped the summary at 8,000, which made a 1M window write the same 8,000-token summary as a 262k one - the constant decided the summary, not the context. Shares replace both.

## Terms

- **W, effective window**: the declared `contextWindow` minus the provider's own output reservation. The reservation is the one number that is not a share of the context: it is what the model itself declares it can emit, clamped to 0.25 of the declared capacity so a model claiming more output than its whole window (393,216 against 32,000) cannot collapse the window to zero - a zero window has no trigger to cross, so it would compact on every turn. A model that declares nothing reserves nothing.
- **F, fixed context**: the measured part of a request a compaction cannot spend - system messages (workspace instructions and per-tool instructions), advertised tool schemas and the retry notice. The user message and the regenerated context block are deliberately excluded, because a compaction replaces them. F is measured from the frozen request, never guessed: the recorded 32k Chat reported 12,426 input tokens on its third turn, about 12,300 of them fixed, of which 3,362 was the system message and 4,344 the tool schemas.
- **Trigger**: 0.80 W by default, and it must stay above the occupancy target; validation rejects a trigger at or below it, because such a run would compact on every request.

## Plan

| quantity | rule |
|---|---|
| target T | floor(0.25 * W) |
| budget B | max(T - F, floor(0.08 * W)) |
| summary S | min(floor(summaryShare * B), declared output reservation) |
| retained tail R | B - S |

The summary takes its share of the replacement budget and the tail keeps the remainder, so both parts scale with the window and keep a constant ratio (0.8 : 0.2 at the default share). The model's own declared output is the only bound that is not a context share: a summary is never asked to be longer than the model says it can emit, and whatever the summary cannot use shifts into verbatim history rather than truncating the plan. When the target is out of reach, the plan is the floor: 8% of the window, still split by the same share.

Worked numbers at F = 12,400, no declared output reservation, default share:

| W | T | B | R | S | occupancy after |
|---|---|---|---|---|---|
| 32,768 | 8,192 | 2,621 (floor) | 2,097 | 524 | 15,021, target missed, one advisory |
| 100,000 | 25,000 | 12,600 | 10,080 | 2,520 | 25,000 = T |
| 262,144 | 65,536 | 53,136 | 42,509 | 10,627 | 65,536 = T |
| 1,048,576 | 262,144 | 249,744 | 199,796 | 49,948 | 262,144 = T |

The summary grows with the context: 2,520 tokens at 100k, 10,627 at 262k, 49,948 at 1M. The tail grows with it, so a large-context model keeps proportionally more of both instead of behaving like a small one. A Chat that sets `summaryShare` to 0.5 gets R 124,872 / S 124,872 at 1M, and the budget is still spent exactly.

A decode-bound local model bounds itself: if it declares an 8,000-token output, S is 8,000 at every window and the rest of B becomes verbatim tail (at 1M: R 241,744, S 8,000). That is the user's own model setting, not a constant this model invents.

Occupancy after one compaction is `F + B`, which equals T whenever the target binds and `F + floor(0.08 W)` when the floor binds. Because the floor plan is below the trigger by construction (`can_reduce`), the run never exceeds its declared window: it compacts every time pressure crosses the trigger. At 32k with F = 12,300 that is about every 5 turns.

## The one quality knob, and where it lives

`summaryShare` is the only ratio with no derivation, so it is the one a Chat sets rather than a constant: it decides prose against verbatim history. It is a share of the replacement budget, not of the window and not a token count, because that is the only framing honoured exactly at every window (`R + S = B` always, no clamping). The failure mode it replaces is instructive: the old `retainRatio` was a share of the *window*, so at 32k it asked for more verbatim history than the window could hold, which is what the 64,000-token floor was hiding.

In Settings the field is **"Summary share of compaction (%)"** (percent, default 20, accepted range 1-90), and it is offered only for a model that declares a context window. A model that declares none gets the absolute verbatim tail (`retainTokens`) instead, because a plan cannot be sized without a window; exactly one of the two controls is shown, so neither can silently do nothing. The panel states the derived numbers - target occupancy, the split, and the output the model reserves for itself - from a pure mirror of this arithmetic, and the runtime's `retainRatio` key is a legacy sink.

Everything else in the model is structural rather than a preference: the target must sit well below the trigger or the run compacts continuously, and the floor must sit below `target - F/W` or every window clamps.

## Derived floor, and why nothing refuses

`minimum_window(F) = ceil(F / (0.25 - 0.08)) = ceil(F / 0.17)` is the smallest window whose target can cover the fixed context plus one replacement. It is derived from the measured F, so it moves with the tool selection the model actually sees: 72,942 at F = 12,400, 72,353 at the recorded Chat's F = 12,300.

- `can_reduce(W, F) = F + floor(0.08 W) < trigger * W` is the only condition that stands automatic compaction down, and it is about headroom, not about a chosen minimum: when the fixed context already reaches the trigger there is nothing to gain and compacting would only oscillate.
- Below the floor the plan is the floor itself (a share, not a token count), the target is simply missed, and compaction still runs. A run that ignores its own declared window is worse than one that compacts badly; the request is unreasonable, but it is honoured.
- The diagnostic is an advisory, never a refusal. `compaction_advisory(W, F)` names the target, F, the floor as a percentage of the window with its token value, and the derived minimum window.
- A standing condition is published once per distinct body through the run event stream's `context_advisory_once`, and a cleared condition re-arms, so a persistent configuration is not re-reported every turn. The recorded 32k run emitted 47 identical warnings and compacted nothing; that pathology is structurally impossible now.

## Invariants

1. Every budget is a share of W, or a function of the measured F, or the model's own declared output. No absolute token count shapes a plan.
2. `R + S = B` exactly, and the split is exactly the configured (or default) share, to within the token a floor rounds away.
3. A window of at least `minimum_window(F)` lands exactly on 0.25 W occupancy.
4. `can_reduce` implies the post-compaction context is below the trigger.
5. Both parts grow with the window, so a larger window never keeps less history than a smaller one.
6. A Chat that declares no window keeps the legacy model-free 512 KiB byte-pressure guard with its absolute verbatim tail; there is no ratio to judge.

## Non-responsibilities

This model owns the budgets only. It does not decide which units may be shadowed, how the post-compaction state block is re-injected, how a failed summary recovers, the pruning gate, or how the summary call is shaped. One gap is tracked separately: a prefix that no longer fits the window must still end in a fitting reduction (task 144).

## Superseded material

The 2026-09-25 R/U/S formulation is no longer the authority: retention is not a knob, U is not a separate budget (user turns ride inside R at up to half of it), S is not R/2, and there is no 64,000-token floor or `headroom >= 0.25 W` freeze check. The 2026-09-26 morning revision's 2,000/512 minima and 8,000 summary cap are also gone, for the reason above. `docs/context-compaction.md` still describes the R/U/S model and is tracked for a documentation pass.
