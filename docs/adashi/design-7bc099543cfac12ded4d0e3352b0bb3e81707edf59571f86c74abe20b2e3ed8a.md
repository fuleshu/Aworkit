# Menu bar cleanup and About dialog

## Scope

The native application menu is reduced to the entries this build actually supports, and Help gains
a real About dialog.

- File: remove `Open Workflow…` (the workflow surface is reached through View, and the file chooser
  never opened a workflow).
- Remove the whole `Window` submenu (its minimize/maximize items duplicate the native caption and
  the View fullscreen entry).
- Help: remove `Keyboard Shortcuts` (the same bindings are visible in Settings and the shortcut
  notification was the only consumer).
- Help: add `About`, which opens the in-app About dialog.

## About dialog

A modal in-workbench dialog, not a native OS message box, because the specification requires the
webpage link to be activatable. Content is static and authored in the renderer; nothing is fetched
at runtime.

## Behavior and contracts

- Selecting the native `About` item emits `aworkit.about` on the `aworkit:native-menu` channel.
- The desktop app shell opens the About dialog for that payload; it owns the open/closed state and
  removes the previous `Keyboard Shortcuts` and `Open Workflow…` handlers.
- The dialog is a modal `<dialog>`: Escape and the Close button dismiss it, and focus returns to the
  control that had it.
- The webpage and GitHub links activate through `tauri-plugin-opener` `openUrl`. A browser-hosted
  preview keeps its normal new-tab behavior; an opener failure becomes an in-workbench notification
  and never navigates the webview.
- `desktop/src-tauri/src/presentation.rs` owns menu construction and the `aworkit.about` id.
- `desktop/src/shell/AboutDialog.tsx` owns the content, the library list and the links.

## Non-goals

- No runtime dependency discovery; the library list is curated.
- No change to Settings, shortcuts or any other menu entry.
